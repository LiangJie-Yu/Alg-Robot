在使用定时器PWM驱动舵机时我发现了问题！现象如下：
```c
95度正占空比8% 
94度正占空比7% 
93度正占空比7% 
92度正占空比7% 
91度正占空比7% 
90度正占空比7%
```
由此可见角度与占空比和实际运动之间非线性关系！
## 了解舵机
首先需要了解舵机控制的本质：舵机通常由周期 **20ms（50Hz）** 的PWM信号控制，高电平脉冲宽度在0.5ms到2.5ms之间对应0到180度（典型值）。通常0.5ms对应0度，1.5ms对应90度，2.5ms对应180度。
不是说设定了一个ARR的值只改变占空比就可以移动到相应的线性位置，而是需要注意高电平在一个周期的时间！
## 重新推算
在此重新整理整数运算
```c
angle=90: (90*40)/180 = 3600/180 = 20，ccr = 5+20 = 25。  
angle=91: (91*40)/180 = 3640/180 = 20.22，但整数除法结果为20，ccr=25。  
angle=92: (92*40)/180 = 3680/180 = 20.44 → 20, ccr=25。  
angle=93: 20.66 → 20, ccr=25。  
angle=94: 20.88 → 20, ccr=25。  
angle=95: (95*40)/180 = 3800/180 = 21.11 → 21, ccr=26。
```
可见CCR的值在90-94度之间是相同的，自然不会有变化
## 核心问题
核心问题：==舵机角度**分辨率太低**==。CCR的计算公式使用了整数除法，导致相邻好几个角度都输出相同的CCR值，造成死区。解决方案：需要提高PWM分辨率，使CCR值能够更精细地变化。
## 解决方案
提高PWM分辨率！让每一度都引起CCR的变化！
提高ARR的值
```c
#include "stm32f10x.h"                  // Device header
```

## PWM频率公式
**PWM 频率 = 定时器时钟频率 / ((PSC + 1) × (ARR + 1))**
定时器时钟通常就是系统主频 72 MHz（除非使用了 APB 预分频器，但 TIM3 挂在 APB1 上，APB1 最大 36 MHz，不过 STM32F103 中当 APB1 预分频系数 ≠ 1 时，定时器时钟会是 APB1 的 2 倍，我们默认配置下 APB1 为 36 MHz，定时器时钟就是 72 MHz）
旧配置中
```c
PSC = 3600 - 1;   // 即 3599
ARR = 400 - 1;    // 即 399
```
PWM 频率 = 72,000,000 / ((3599+1) × (399+1))  
= 72,000,000 / (3600 × 400)  
= 72,000,000 / 1,440,000  
= **50 Hz** 
只是分辨率低

新配置中
```c
PSC = 72 - 1;     // 即 71
ARR = 20000 - 1;  // 即 19999
```
PWM 频率 = 72,000,000 / ((71+1) × (19999+1))  
= 72,000,000 / (72 × 20,000)  
= 72,000,000 / 1,440,000  
= **50 Hz** 
分辨率从400步提高到了20000步，分辨率高
